# Universal solve mode review

This is a thorough review of the current universal-solve integration. Commands run during review:

- `cargo test -q`
- `cargo test -q test_universal -- --nocapture`
- `cargo clippy -q --all-targets --all-features`
- small release `tools/solve-snapshot` concrete sweep vs `origin/main`

All existing tests/clippy passed. The issues below are either correctness/API issues, documentation mismatches, or concrete-mode performance concerns.

## High-priority correctness/API issues

### 1. Universal eager conditional requirements skip target-package lock/excluded handling

In `src/solver/encoding.rs`, target packages are queued only for unconditional requirements:

```rust
.filter(|requirement| requirement.condition.is_none())
```

But universal mode encodes conditional requirements eagerly:

```rust
Some(_) if self.state.universal_mode => {
    self.queue_requirement_candidates(solvable_id, requirement, None)
}
```

That path fetches candidate lists for the requirement target, but does **not** run `on_candidates_available` for that target package unless the package is referenced elsewhere. `locked` and `excluded` clauses can be skipped for packages that appear only as targets of universal conditional requirements. The solver can then select an excluded/non-locked candidate.

Suggested fix: before the universal eager `queue_requirement_candidates`, queue the requirement target packages, mirroring `on_condition_data_available` / `queue_deferred_requirement`.

### 2. `UniversalSolution::project` ignores `environment_model`

Docs say `project()` returns `None` for environments outside the environment model, but it only checks cell conditions:

```rust
pub fn project(&self, eval: impl Fn(&EnvLiteral<N>) -> bool) -> Option<&[Id]>
```

A cell can be broader than the model. Example: model is `cuda >= 11`, no dependency uses cuda, and the only cell is `<all environments>`. `project(|_| false)` currently returns the solution even though the machine is outside the model.

Suggested fix: first evaluate the CNF `environment_model`; return `None` if it is not satisfied.

### 3. Invalid public input currently panics

Examples:

- Empty model disjunction: `src/solver/universal.rs:1298`
- Model/seed references a concrete package: `src/solver/universal.rs:1364`
- Model/seed absent literal for `can_be_absent: false`: `src/solver/universal.rs:1328`, `1435`
- Env/concrete union requirements: `src/solver/encoding.rs:552`

These are public API inputs. Panics make sense for internal invariants, but not for model/seed/problem validation.

Suggested fix: add `UniversalFailure::InvalidInput { message }`, or a separate `UniversalProblemError`/validation step. Same for unsupported env/concrete unions.

### 4. Contradictory environment models are handled inconsistently

An empty disjunction (`[[]]`) panics as an unsatisfiable model, but a logically contradictory non-empty model (`[L] AND [not L]`) appears to return success with zero cells, because no environment satisfies the model. Either behavior can be defended, but the current split is surprising. Prefer a single, documented semantics.

### 5. Env-only `Requirement::Union` is not rejected, but conflict display assumes env requirements are `Single`

Encoding only rejects mixed env+concrete unions. An all-env union is allowed. Conflict rendering special-cases only `Requirement::Single(vs)` environment requirements; a failing all-env union can fall through to concrete candidate lookup for an environment package and panic.

Suggested fix: either reject all env unions for v1, or fully support env unions in conflict graph/display.

## Concrete-mode performance concerns

The current branch does some extra work when universal solving is not enabled.

### 1. Hot propagation loop has universal-only accounting/branches

Every propagated decision now does:

```rust
self.state.propagated_total += 1;
if let Some(deadline) = self.state.prefix_budget_deadline { ... }
if self.state.env_ordering_work_deadline.is_some_and(...) { ... }
```

For concrete solves, these are unused. This is in the hottest loop.

Suggested fix: gate universal-only budget accounting behind `if self.state.universal_mode` or another cheap boolean. Keep diagnostics counters under `#[cfg(feature = "diagnostics")]` where possible.

### 2. Requirement/constraint classification adds cache-hit overhead in concrete solves

Universal support changed concrete paths to classify packages via `get_or_cache_candidates` before then calling sorted/matching/non-matching helpers, which often call `get_or_cache_candidates` again. Cache hits are cheap but visible at corpus scale.

Potential fixes:

- Add concrete fast paths when `!state.universal_mode`.
- Or add cache helpers that classify once and compute sorted/matching/non-matching candidates from the already fetched package data.

### 3. `DecideQueue::route_touched` pays an env-constrains lookup in concrete solves

Every touched variable can hit `clauses_by_env_var`. In concrete solves this map is always empty.

Suggested fix: guard with `if !clauses_by_env_var.is_empty()` or track `has_env_constrains`.

## Documentation/API clarity issues

- `docs/design/universal-solve.md` says plain `solve` with environment packages yields “all environment literals false”. Env constraints can force/decide `Absent` or `Matches`; tests exercise that. Update wording to “environment literals default false unless forced by env requirements/constraints”.
- `VersionSetRelation` docs say a wrong `Disjoint` or `Subset` breaks lockfiles; wrong `Superset`/`Equal` are equally dangerous.
- `UniversalSolution::verify` intentionally ignores overlaps between cells with identical solvable sets, while `UniversalSolution::cells` docs say cells are pairwise disjoint. Clarify “partition” vs “semantically harmless overlap”.
- Consider deriving/feature-gating `serde` for `EnvLiteral`, `CellCondition`, `Presence`, `CellEdge`, and maybe `UniversalSolution` if these are intended lockfile-facing types.
- `EnvironmentModel = Vec<Vec<(EnvLiteral, bool)>>` is compact but easy to misuse. A `SignedEnvLiteral` type or builder API would make polarity clearer.

## Algorithm improvement opportunities

- Disjointness proof misses implication cases like `not A` vs `B` where oracle proves `B subset A`. Supporting positive-vs-negative implication disjointness would reduce repair literals and verifier false positives.
- `merged()` simplification only merges exact same literal sets differing in one sign. It does not use oracle/model implications, so presence expressions can remain more fragmented than necessary.
- `run_scoped_conflict` swallows cancellation during the scoped re-solve and returns the fallback conflict. If cancellation is user-requested, it should probably propagate as `UniversalFailure::Cancelled`.

## Misc cleanup

There is an unstaged local size probe in `src/solver/clause.rs`:

```rust

```

Probably remove before merging.

# Red-test designs for incorrect cases

These tests are intended to fail on the current implementation and pass after the corresponding fixes. They are written to paste into `tests/solver/main.rs`, near the existing universal tests, where helpers like `parse_env_literal`, `transaction_to_string`, `BundleBoxProvider`, and `Pack` are in scope.

## Test 1: `project()` must reject concrete environments outside the model

Current failure mode: `project(|_| false)` returns `Some([a])` because the only cell is `<all environments>`, even though the model requires `cuda >= 11`.

```rust
#[test]
fn test_universal_project_respects_environment_model() {
    let mut provider = BundleBoxProvider::new();
    provider.add_environment_package("cuda", true);
    provider.add_package("a", Pack::new(1), &[], &[]);

    let requirements = provider.requirements(&["a"]);
    let model = vec![vec![parse_env_literal(&mut provider, "cuda 11..100")]];

    let mut solver = Solver::new(provider);
    let solution = solver
        .solve_universal(
            UniversalProblem::new()
                .requirements(requirements)
                .environment_model(model),
        )
        .expect("solvable");

    // `cuda` is not load-bearing, so the cell is broader than the model.
    assert_eq!(solution.cells.len(), 1);
    assert!(solution.cells[0].0 .0.is_empty());

    // A machine where cuda>=11 is false is outside the model and must not
    // project to a cell.
    assert!(
        solution.project(|_| false).is_none(),
        "project() must reject environments outside the environment model"
    );

    // A machine satisfying the model still projects successfully.
    assert!(
        solution
            .project(|literal| matches!(&literal.kind, EnvLiteralKind::Matches(_)))
            .is_some()
    );
}
```

## Test 2: Universal eager conditional target packages must still encode `locked` metadata

Current failure mode: `b=2` is selected because the package `b` appears only as the target of a conditional requirement, and universal eager conditional encoding does not run `on_candidates_available` for `b`, so the lock on `b=1` is never encoded.

```rust
#[test]
fn test_universal_eager_conditional_target_package_lock_is_encoded() {
    let mut provider = BundleBoxProvider::new();
    provider.add_environment_package("cuda", true);
    provider.add_package("a", Pack::new(1), &["b 0..3; if cuda 11..100"], &[]);
    provider.add_package("b", Pack::new(1), &[], &[]);
    provider.add_package("b", Pack::new(2), &[], &[]);
    provider.set_locked("b", 1);

    let requirements = provider.requirements(&["a"]);
    let model = vec![vec![parse_env_literal(&mut provider, "cuda 11..100")]];

    let mut solver = Solver::new(provider);
    let solution = solver
        .solve_universal(
            UniversalProblem::new()
                .requirements(requirements)
                .environment_model(model),
        )
        .expect("solvable");

    let chosen = solution.cells[0]
        .1
        .iter()
        .map(|&s| solver.provider().display_solvable(s).to_string())
        .sorted()
        .collect::<Vec<_>>();

    assert!(chosen.contains(&"a=1".to_string()));
    assert!(
        chosen.contains(&"b=1".to_string()),
        "the locked candidate b=1 must be chosen"
    );
    assert!(
        !chosen.contains(&"b=2".to_string()),
        "b=2 must be forbidden by the package lock"
    );
}
```

A sibling excluded-candidate variant is also valuable:

```rust
#[test]

    provider.exclude("b", 2, "broken");

    let solution = solver
        .solve_universal(
            UniversalProblem::new()
                .requirements(requirements)
                .environment_model(model),
        )
        .expect("solvable");

    let chosen = solution.cells[0]
        .1
        .iter()
        .map(|&s| solver.provider().display_solvable(s).to_string())
        .sorted()
        .collect::<Vec<_>>();

    assert!(chosen.contains(&"b=1".to_string()));
    assert!(!chosen.contains(&"b=2".to_string()));
}
```

## Test 3: Env-only union conflicts must not panic during display

Current failure mode: an all-env `Requirement::Union` can be allowed by encoding but conflict display only handles `Requirement::Single` as an environment requirement. The union can fall through to concrete candidate lookup for an environment package and panic.

```rust
#[test]
fn test_env_only_union_conflict_display_does_not_panic() {
    let mut provider = BundleBoxProvider::new();
    provider.add_environment_package("cuda", false);

    // The union requires cuda in either [0,5) or [11,100), while the second
    // root requirement forces cuda in [6,10). The oracle proves both union
    // alternatives disjoint from the forced literal.
    let requirements = provider.requirements(&[
        "cuda 0..5 | cuda 11..100",
        "cuda 6..10",
    ]);

    let mut solver = Solver::new(provider);
    let problem = Problem::new().requirements(requirements);
    let conflict = match solver.solve(problem) {
        Err(UnsolvableOrCancelled::Unsolvable(conflict)) => conflict,
        other => panic!("expected unsolvable env-union conflict, got {other:?}"),
    };

    let display = conflict.display_user_friendly(&solver).to_string();
    assert!(
        display.contains("environment"),
        "env-only union conflicts should render as environment requirements, not panic"
    );
}
```

## Test 4: Empty / contradictory models should use one documented error path

This one depends on the chosen API fix. If the fix adds `UniversalFailure::InvalidInput`, add tests like:

```rust
#[test]
fn test_universal_empty_model_clause_is_invalid_input_not_panic() {
    let provider = BundleBoxProvider::new();
    let mut solver = Solver::new(provider);
    let result = solver.solve_universal(
        UniversalProblem::new().environment_model(vec![vec![]]),
    );
    assert!(matches!(result, Err(UniversalFailure::InvalidInput { .. })));
}
```

And decide the desired behavior for logically unsatisfiable but non-empty models (`[L] AND [not L]`): either also `InvalidInput`, or `Ok` with zero cells. Add a test that locks that choice down.

## Test 5: Scoped conflict cancellation should propagate

If `run_scoped_conflict` is changed to propagate cancellation instead of falling back to the unscoped conflict, add a provider that returns `should_cancel_with_value()` only after the witness has been found and the scoped re-solve begins. Then assert `solve_universal` returns `Err(UniversalFailure::Cancelled(_))` rather than `Unsolvable` with fallback conflict.
