# Hardening the universal-solve property test

The current property test (`src/solver/universal_prop.rs`) is valuable, but it only checks the universe it generates and the properties it asserts. The review issues mostly sit outside that generated domain. This document outlines how to extend the property suite so the same style of randomized/exhaustive checking catches those classes too.

Terminology: this is not currently using the `proptest` crate; it is a deterministic seeded property/fuzzer. The proposals below keep that model unless explicitly noted.

## Goals

1. Keep the existing fast semantic property: successful universal solves form a valid cover of the modeled environments; failures have unsolvable witnesses.
2. Add negative/out-of-model checks that the current property does not assert.
3. Expand generated provider features so public API metadata (`locked`, `excluded`, unions, invalid inputs) is exercised.
4. Add a small set of adversarial templates for rare-but-important cases instead of relying on probability alone.
5. Keep the default test runtime reasonable; put slower or corpus-like sweeps behind `#[ignore]` or an env var.

## Current blind spots and proposed changes

### 1. `UniversalSolution::project` must respect `environment_model`

**Why current property misses it**

The property only calls `project()` for environments that satisfy the model:

```rust
if !model_satisfied(&universe, &env) {
    continue;
}
```

So it never checks the documented behavior outside the model.

**Change**

In the `Ok(solution)` branch, after the in-model exhaustive loop, add an out-of-model loop over the same tiny exhaustive environment space:

```rust
for env in enumerate_envs(&universe) {
    if model_satisfied(&universe, &env) {
        continue;
    }

    let projected = solution.project(|literal| {
        eval_env_literal(provider, &env_name_ids, literal, &env)
    });

    assert!(
        projected.is_none(),
        "seed {seed}: project() returned a cell for out-of-model env {env:?}"
    );
}
```

This catches cells that intentionally/generalizedly extend outside the model unless `project()` checks the model first.

**Note**

This test encodes the current docs. If the API decision is instead “`project()` ignores the model and callers must check it”, update the docs and add a separate `project_with_model()` helper; otherwise enforce this property.

### 2. Locked/excluded metadata skipped for universal eager conditional target packages

**Why current property misses it**

`EnvTestProvider` has no `locked`, `excluded`, or `favored` package metadata. It always returns plain `Candidates { candidates, ..Default::default() }` for concrete packages. The generator therefore cannot observe whether universal eager conditional encoding forgot to call `on_candidates_available()` for a target package.

**Provider extension**

Extend `EnvTestProvider` with optional concrete-package metadata:

```rust
struct EnvTestProvider {
    // existing fields...
    locked: HashMap<NameId, SolvableId>,
    excluded: HashMap<SolvableId, StringId>,
}
```

and in `get_candidates`:

```rust
let mut candidates = Candidates { candidates, ..Default::default() };
candidates.locked = self.locked.get(&name).copied();
candidates.excluded = candidates
    .candidates
    .iter()
    .copied()
    .filter_map(|s| self.excluded.get(&s).map(|&reason| (s, reason)))
    .collect();
Some(PackageCandidates::Candidates(candidates))
```

Add test helpers:

```rust
fn lock_package_version(&mut self, pkg: usize/name, version: u32) { ... }
fn exclude_package_version(&mut self, pkg: usize/name, version: u32, reason: &str) { ... }
```

**Generator extension**

Add metadata to `ConcretePkg`:

```rust
struct ConcretePkg {
    versions: Vec<PkgVersion>,
    locked: Option<u32>,
    excluded: Vec<u32>,
}
```

Generate metadata with low probability, biased toward packages with at least two versions:

- 10-20%: lock one version.
- 10-20%: exclude one or more versions, but avoid excluding every version unless intentionally generating unsat cases.

**Oracle extension**

Update `is_valid_solution()` so projected install sets obey metadata:

- If a package has `locked = Some(v)` and any version of that package is installed, it must be `v`.
- No installed version may be in `excluded`.

Also update brute-force enumeration used on failure to only consider non-excluded / lock-compatible installs.

**Adversarial template**

Do not rely only on random generation. Add a deterministic template to the seed loop (or a separate test in the property module):

- env package `env0`, model forces `env0 in [1, 2)`.
- package `a=1` has conditional requirement `b * if env0 in [1, 2)`.
- package `b` has versions `1` and `2`, sorted highest first.
- lock `b=1` or exclude `b=2`.
- root requires `a`.

The target package `b` appears only as the target of a universal conditional requirement. This should catch the eager-path bug reliably.

### 3. Invalid public inputs should not panic

**Why current property misses it**

The generator only builds valid input:

- model clauses are non-empty;
- model literals only reference environment packages;
- absent literals are generated only for `can_be_absent` packages;
- seeds come from previously produced cells.

**API decision first**

Choose a public API behavior before writing the property:

- Preferred: return `Err(UniversalFailure::InvalidInput { .. })` or a separate validation error.
- Alternative: expose `UniversalProblem::validate()` and keep `solve_universal` assuming validated input.

Once chosen, add a separate negative property/test group.

**Negative generators**

For each generated valid provider/universe, derive invalid problems by mutation:

1. Empty model clause:
   ```rust
   environment_model = vec![vec![]]
   ```
2. Model references a concrete package:
   - create `EnvLiteral { package: concrete_name, kind: Matches(concrete_version_set) }`.
3. Model uses `Absent` for an env package with `can_be_absent = false`.
4. Seed references a concrete package.
5. Seed uses `Absent` for a non-absent env package.
6. Matches literal package/version-set mismatch, if the public type keeps both fields.

**Assertion shape**

After the API is fixed:

```rust
let result = solver.solve_universal(problem);
assert!(matches!(result, Err(UniversalFailure::InvalidInput { .. })));
```

Before the API is fixed, a temporary regression test can use `catch_unwind` to document the current panic, but the desired hardening property should assert “does not panic”.

### 4. Env-only and mixed `Requirement::Union` cases

**Why current property misses it**

`GenRequirement` currently builds exactly one `VersionSetId`, so every generated requirement is `Requirement::Single`.

**Generator model change**

Replace or augment `GenRequirement` so a requirement can have multiple alternatives:

```rust
struct GenRequirement {
    alternatives: Vec<GenRequirementAtom>,
    condition: Option<GenCondition>,
}

struct GenRequirementAtom {
    target: GenTarget,
    lo: u32,
    hi: u32,
}
```

Build as:

- one alternative -> `Requirement::Single(version_set)`;
- multiple alternatives -> intern version-set union.

Generate union classes deliberately:

1. all-concrete union (should work; catches regressions in existing behavior);
2. all-env union;
3. mixed env+concrete union.

**Expected behavior choices**

There are two viable v1 choices:

- Reject every union containing environment version sets as invalid input.
- Support all-env unions, reject only mixed unions.

Whichever is chosen, encode it in the property.

If rejecting:

```rust
assert!(matches!(result, Err(UniversalFailure::InvalidInput { .. })));
```

If supporting all-env unions, update oracle logic:

- A requirement is satisfied when at least one alternative is satisfied.
- Concrete alternative: an installed solvable of the target package has a version in range.
- Env alternative: the concrete environment satisfies the env literal.

**Conflict-display check**

The current env-union concern is partly in conflict rendering. In every `Err(UniversalFailure::Unsolvable { conflict, .. })` branch, add:

```rust
let _ = conflict.display_user_friendly(&solver).to_string();
```

This catches panics in conflict graph/display for generated unsat cases, including env-only union cases if they are generated.

Add a deterministic adversarial template for an unsat all-env union, because random generation may be too sparse:

- `root`: `(env0 in [0, 5) OR env0 in [11, 100))` and `env0 in [6, 10)`.
- oracle says both alternatives disjoint from `[6, 10)`.
- assert unsat displays without panic.

### 5. Contradictory / empty environment models

**Why current property misses it**

The generator avoids empty model clauses. It can generate contradictory non-empty models, but the property treats “no environments admitted by the model” as vacuously successful because it only iterates admitted environments.

**Classify model satisfiability**

Add a helper:

```rust
fn model_has_any_environment(universe: &Universe) -> bool {
    enumerate_envs(universe).any(|env| model_satisfied(universe, &env))
}
```

Then make the expected API behavior explicit.

**If vacuous success is desired**

Assert:

- `solve_universal` may return `Ok(solution)`;
- `solution.cells` should probably be empty;
- `solution.project(...)` should return `None` for every concrete environment;
- `merged()` and `edges()` should be empty or otherwise documented.

**If invalid-input is desired**

Assert contradictory models return invalid-input errors, just like empty clauses.

**Add generated invalid model modes**

Generate a small fraction of explicit model shapes:

1. empty clause: `false`;
2. direct contradiction: `[L] AND [not L]`;
3. oracle contradiction: `[L_a] AND [L_b]` where `a` and `b` are disjoint;
4. absent/present contradiction: `[Absent] AND [Matches]` for same package.

These should live in a separate negative property if their expected result differs from normal solving.

### 6. Scoped conflict cancellation

**Why current property misses it**

The generator does not control cancellation timing. It tests normal successful/unsuccessful solving, not cancellation during the scoped re-solve performed after an uncovered unsolvable region is found.

**Provider support**

Add a cancellation mode to `EnvTestProvider`, e.g. shared state:

```rust
struct CancelState {
    should_cancel_after_calls: Option<usize>,
    calls: Cell<usize>,
}
```

and in `should_cancel_with_value` increment/check the counter.

This is somewhat brittle because the number of cancellation checks can change as the solver evolves.

**More robust test hook**

Prefer a narrow test-only hook in the solver or provider:

- provider exposes a flag that starts returning cancellation only after a marker method is called;
- `run_scoped_conflict` (behind `#[cfg(test)]`) marks “scoped re-solve started”; or
- a test-only provider infers scoped phase by seeing a second root solve after the first unsat witness, if this can be made deterministic.

**Property assertion**

Once cancellation can be triggered reliably during scoped re-solve:

```rust
assert!(matches!(
    solver.solve_universal(problem),
    Err(UniversalFailure::Cancelled(_))
));
```

This should be a targeted regression test rather than part of the main 1000-seed loop.

## Structure recommendation

Keep `test_universal_solve_property` focused and fast, but split the property suite into layers:

### A. Main semantic property (existing + small additions)

- Keep 1000 seeds.
- Add out-of-model `project()` assertions.
- Add conflict display smoke test in unsat branch.
- Maybe add low-probability locked/excluded metadata once provider/oracle support exists.

### B. Adversarial template tests

Add deterministic hand-built universes inside `universal_prop.rs` or `tests/solver/main.rs` for:

1. conditional-only target package with lock/exclusion;
2. out-of-model projection with broad empty cell;
3. all-env union unsat display;
4. contradictory model chosen semantics;
5. scoped conflict cancellation.

These should not depend on random generation.

### C. Negative input property

A separate test that mutates generated valid universes into invalid `UniversalProblem`s and asserts the public error path. This should be added after invalid input stops panicking.

### D. Optional slow/fuzz mode

Allow increasing seed count via env var:

```rust
let seed_count = std::env::var("RESOLVO_UNIVERSAL_PROP_SEEDS")
    .ok()
    .and_then(|s| s.parse().ok())
    .unwrap_or(SEED_COUNT);
```

This lets CI run the fast default while local/nightly runs explore more generated unions/metadata combinations.

## Concrete implementation checklist

1. Add out-of-model `project()` assertion to the existing success branch.
2. In unsat branches, call `conflict.display_user_friendly(&solver).to_string()` to catch display panics.
3. Extend `EnvTestProvider` with `locked` and `excluded` metadata.
4. Extend `Universe::ConcretePkg` metadata and update `build_provider`.
5. Update `is_valid_solution` and brute-force search to respect lock/exclusion metadata.
6. Refactor `GenRequirement` to support unions.
7. Decide env-union semantics; assert either invalid-input or full support.
8. Decide contradictory/empty model semantics; assert consistently.
9. Add adversarial templates for the known bug shapes.
10. Add cancellation-phase test support, preferably with a deterministic test hook.

## What property tests still should not try to catch

Performance regressions in concrete mode are better caught by benchmarks or diagnostics-counter tests, not semantic property tests. The property can assert state invariants such as “plain solves with no env packages never set `env_ordering_active`”, but it cannot prove that a few extra hot-loop branches are cheap enough. Keep those in benchmark CI or a targeted perf guard.
